# Atlas for Android

Native Android frontend for [LMS147/atlas-agent](https://github.com/LMS147/atlas-agent), inspired by the supplied Atlas screen reference.

## Run

1. Extract this project and open `android` in Android Studio.
2. Use JDK 17 and install Android SDK 35 through SDK Manager.
3. Sync Gradle, then run `app` on an Android 8.0+ emulator or device.
4. Tap **Explore demo**. No credentials or backend are required for the preview.

Command line, with the SDK configured in `local.properties` or `ANDROID_HOME`:

```sh
./gradlew testDebugUnitTest assembleDebug
```

Windows:

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

The debug APK will be at `app/build/outputs/apk/debug/app-debug.apk`.
Pinned toolchain: Gradle 8.11.1, Android Gradle Plugin 8.9.2, Kotlin/Compose compiler 2.1.20, Compose BOM 2025.04.01. These are deliberate fixed versions, not claims of the latest versions.

## Included

- Welcome and server setup screens; demo mode with explicit labels.
- Material 3 dark theme, blue/cyan branding, navigation drawer, quick actions.
- Chat composer, local history, timestamps, loading and error states.
- Searchable memory, section filtering, and manual memory creation.
- Read-only agent profile and file listing; server health refresh.
- Settings, local chat clearing confirmation, disconnect/credential removal.
- MVVM, repository, Retrofit/OkHttp, Room cache, Android Keystore AES-GCM credential storage.
- Gradle wrapper and API URL validation unit tests.

## Backend boundary

The existing repository contains a Telegram bot with `agent.py`, `memory.py`, and file/GitHub memory storage. It does **not** currently expose the HTTP endpoints this app needs. The live connection screen will only succeed after the FastAPI adapter implements [the proposed API contract](../docs/api.md). No Python backend, Groq inference, tunnel, or Termux service is added in this frontend phase.

Demo chat replies are deterministic explanatory text, not AI output. Demo memories and files are examples. Server metrics are not fabricated. File editing, attachments, command execution, agent editing, and remote session reset are not implemented. The Tools screen explains this boundary.

## Data and credentials

The app asks for an **Atlas access token**, not the Groq key. The Groq key must stay in the server environment. The token is attached only to requests sent to the configured server; HTTPS is required, redirects and automatic connection retries are disabled. Only connect to a server you trust. Cloudflare Access service-token headers are not implemented; use a tunnel exposing the app API with its own bearer-token validation in the first backend version.

Remembered URL/token pairs are encrypted with an AES-GCM key generated by Android Keystore. Backup is disabled. Tokens are not saved in Room or logs. Cache rows are separated by server and token identity; demo data has its own scope. Room chat/memory content is ordinary app-private SQLite, not an encrypted database. Disconnect removes saved credentials but retains caches; clear local chat removes only the current workspace's messages. This does not reset the server session. Timestamp preference is kept during the current app process only.

## Structure

```text
app/src/main/java/com/atlas/ai/
  MainActivity.kt
  navigation/AtlasViewModel.kt
  data/
    local/               Room entities
    model/               API wire models
  core/security/         Keystore-backed credential encryption
    remote/              Proposed HTTP API
  core/network/          HTTPS validation and Retrofit construction
    repository/          Remote/demo data and cache boundary
  navigation/AtlasApp.kt App shell
  feature/               Compose feature screens
  ui/theme/              Common colors and components
```
